## 本版功能

- **自动收集付款通知**：在「我的 → 开启自动记账」阅读说明后，再到安卓系统授予通知使用权。原生通知服务只筛选微信和支付宝的部分中文支付成功 / 收款 / 退款 / 转账通知，保存在本机 SQLite 队列；普通聊天、验证码和通知原文不入库、不上传。当前解析规则尚需用真实通知验证。
- **集中核对**：通知金额明确时添加待核对账目，确认前不计入收支；缺失或歧义金额单独待补全。相近时间金额不盲目合并，退款、转账单独核对。同一事件重送不会重新创建记录，删除标记也会保留。
- **真实状态**：分别显示应用采集开关、系统授权、原生监听连接、最近成功采集和错误。未连接可刷新重连，省电与通知权限另有系统设置入口。没有新通知不等于服务故障。
- **学习续接**：添加学习内容、下一步、HTTPS 资料地址；5–240 分钟计时，可暂停继续，重开应用恢复剩余时间。文字断点记录章节 / 视频时间 / 下一步，保留 URL 的集数和进度参数。课表按用户确认的六个时段手动添加。
- **本机保存**：原生 SharedPreferences 备份整份手机状态，WebView 存储迁移后保留作镜像；原生队列只有在手机状态保存成功后才确认消费。账本 JSON 只交换账目；手机完整备份另含计划、断点等资料，恢复前预览并明确确认替换。
- **伙伴**：应用内初华待机和点击随机动作，不申请悬浮窗权限。

## 使用边界与真机验证

微信内付款成功不保证发出安卓系统通知；没有通知就无法自动收集，需导入微信 / 支付宝账单补漏。银行卡目前支持手动记录和文件导入，未接自动通知采集。当前规则不读取订单商品列表，不承诺每笔消费零遗漏。

计时在回到应用时按绝对结束时间结算，不保证后台准点响铃。课表尚未接教务自动导入、电脑同步或课后提醒；断点不持续截屏，不启用手机屏幕监控。

需要红米 K70 Pro 验证：通知实际模板及金额展示、息屏付款通知、重启 / 强制停止后的连接、系统返回键、系统栏和键盘、文件选择、分享备份、应用更新和清除 WebView 存储后的恢复。卸载或清除应用数据会删除本机资料，更新前应主动备份。

## 从 0.1.0 更新

0.1.0 使用临时 CI 调试签名，无法取回同一个签名密钥。本版改用所有者保管的固定测试签名，因此首次换版可能无法直接覆盖旧包。先在旧版「我的 → 导出备份」保存账本，再卸载旧测试版、安装新版，并从账本页导入。不能在未备份时通过清空数据解决安装问题。本版之后沿用同一测试签名并递增 versionCode。

所有者签名资料保存在本机发布目录 `Android/signing/`，不提交 Git；GitHub 仅持有加密的 Actions secrets。只分享 APK，切勿将签名目录一并发送。正式上架应另行确定正式包名、长期签名和发布流程。

## 构建与检查

需要 Node 22+、JDK 21、Android SDK 36。工程已经生成：

```sh
cd mobile
npm ci
npm run android:sync
cd android
./gradlew testDebugUnitTest assembleDebug
```

Windows 使用 `gradlew.bat`。本地未配置签名环境变量时使用本机调试签名，不能与 CI 的包混作同一个更新渠道。固定签名构建使用 `STUDYTRAIL_KEYSTORE` 和 `STUDYTRAIL_STORE_PASSWORD` 环境变量，不在命令行输出密码。

手动运行 GitHub Actions **Android preview**，从 `StudyTrail-Android-preview` artifact 获取 APK。流程运行 Java 单元测试、编译 APK，并用 apksigner 验证签名，不创建 Release。测试包名：`com.studytrail.mobile.preview`。

本地检查：`tools/verify-mobile.cjs` 11 项手机页面 / 学习流程，`tools/verify-mobile-capture.cjs` 6 项通知入账规则。Android JUnit 另验证 9 项支付解析规则；仍不能替代真机通知和后台测试。
